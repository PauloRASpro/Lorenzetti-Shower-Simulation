# Original experiment artifacts

This directory stores the original result artifacts generated by the Lorenzetti calibration experiments. To accommodate GitHub file-size limits, large artifact collections may be distributed as multipart **7z archives**, split into approximately 50 MB volumes (`.7z.001`, `.7z.002`, `.7z.003`, etc.). Extract the archives before loading the results in the notebooks.

## 1\. Download and extract the 7z archives

Download **every part** of each archive and place the parts together in the same directory. Keep the original filenames and sequence numbers. Start extraction **only from the first part** (`.7z.001`); the extraction program will automatically read the remaining parts.

### Windows

1. Install [7-Zip](https://7-zip.org/).
2. Right-click the file ending in `.7z.001` (not `.002` or later).
3. Select **7-Zip → Extract Here** or **7-Zip → Extract to ...**.
4. Allow 7-Zip to combine the volumes and extract the files.

### macOS

1. Install [Keka](https://keka.io/) or [The Unarchiver](https://theunarchiver.com).
2. Open the first volume ending in `.7z.001` with the extraction application.
3. The application will combine the parts and extract their contents.

### Linux

With 7-Zip installed, open a terminal in the folder containing the archive parts and run:

```bash
7z x filename.7z.001
```

Replace `filename.7z.001` with the actual first-volume filename. Install 7-Zip through your distribution's package manager if the `7z` command is unavailable (for example, `sudo apt install p7zip-full` on distributions that provide that package).

> \\\*\\\*Important:\\\*\\\* Do not extract `.7z.002`, `.7z.003`, or subsequent parts individually. Do not rename the parts.

## 2\. Place the extracted artifacts

The original `\\\*.pkl` and `\\\*.pkl.gz` files must be available directly in `artifacts/pickles/`, retaining their original filenames. If extraction creates an additional parent directory, move the extracted files into `artifacts/pickles/` without renaming them.

Typical filenames include:

```text
BDT\\\_noSEG\\\_Full\\\_DF.pkl.gz
BDT\\\_noSEG\\\_performance\\\_metrics.pkl.gz
BDT\\\_noSEG\\\_cv\\\_metrics\\\_df.pkl.gz
integrated\\\_result\\\_BDT\\\_noSEG\\\_Full\\\_DF.pkl.gz
RFBDT\\\_noSEG\\\_Full\\\_DF.pkl.gz
DNN\\\_noSEG\\\_Full\\\_DF.pkl.gz
GNN\\\_noSEG\\\_Full\\\_DF.pkl.gz
```

The full event DataFrames preserve the prediction and Monte Carlo truth columns. Integrated results retain the energy and pseudorapidity intervals used for segmented analyses. The notebooks load the model families relevant to each publication and identify unavailable inputs when required.

**Do not decompress `.pkl.gz` files separately:** they are the compressed pickle files expected by the analysis code. The multipart `.7z` archive is the outer distribution layer.

## 3\. Timing metadata and trained models

The `\\\*\\\_noSEG\\\_times.pkl` files may contain serialized trained estimators and can be particularly large. When these files are available locally, the notebooks can extract numerical timing metadata into `artifacts/metadata/prediction\\\_times.csv`; trained model objects are not copied into that CSV.

Keep the historical artifacts unchanged. New experiment runs are stored separately under `artifacts/new\\\_runs/` and must not overwrite these files.

## 4\. Storage and security

Only unpickle files from sources you trust: Python pickle loading can execute arbitrary code. For large public artifacts that exceed normal GitHub limits, use Git LFS or a versioned scientific data archive and document the download location.
